# AFR 单篇文章白板标准

2026-11-26 · 适用于文章 Agent 的研读、独立校读、返工与重划分。交付的是一张直接可读的单篇白板，以及可按原序阅读的完整文章。

## 划分白板

- 按文章的主线设置主题列，沿用作者论述顺序。同一主线中的卡片共享一个 `branch`。列名帮助导航，卡片标题点明对象及有据可查的判断或关系。
- 一张内容卡承载一个能独立复述的判断。同一判断的原因、中间推导、例子、反例和适用条件尽量放在一起。两个论证各自具备判断及依据时拆卡，段落换行和小标题只是参考。
- 按编号连续覆盖可读原文，保留固定定位。正文中的开场、推广、口头重复和免责声明仍可回读，卡片只提炼与论证有关的内容。纯资料说明可以概括其范围和用途。
- 转写的一条固定段落可能连讲两件事。如果分界落在同一个编号内，保留原编号，用卡面里的短段落明确交代话题转换，并在能划开的固定段落边界拆卡。
- 文章白板与知识总结白板使用同一套浅色、低饱和配色。一条观点链的内容卡片、主题标签、连线和续列使用同一颜色，相邻观点链使用可区分的颜色。文章入口与阅读地图使用独立的浅暖灰。程序按 `branch` 统一上色，续列延续原主线，文字标签仍负责说明内容归属。

## 写卡片正文

- `summary` 是白板上直接展示的正文。一般用 3–5 句，写清谁提出了什么判断、为什么，以及影响理解的条件、证据或例子。长度随完整论证调整。读者合上原文后应能复述卡片的主张和推导。同一个标题或「查看原文」之类的提示不能充当正文。
- 把已披露事件、作者解释、转述和预测写成各自的口径。决定结论的数字应带单位、分母或范围、时点及主体。遇到转写含混、数据缺来源、段内说法冲突或材料未读到的地方，在卡片中标清其影响。
- 每张卡的标题打开同一篇下的独立论述白板，连续呈现该话题的完整签发正文、适用条件和有据可查的引文。论述保留固定原文入口、准确的阅读段号与返回文章白板的链接。链接由程序根据 `start` 与 `end` 生成。完整阅读保留原段和顺序。原文保全模式仍要写 `summary`，程序会保留该组的完整原文。

## 把已校读的观点交给下一步

在同一次研读中，为每组有实质判断的内容填写 `viewpoints`。每条只写一项可以核对的判断。记录以下内容。

| 字段 | 怎么填 |
| --- | --- |
| `judgment`、`speaker`、`kind` | 写明谁作了什么判断，区分已披露的事实、解释、预测、建议和仍未确定的说法。转述保留原说话者，身份不明就直说。 |
| `grounds`、`conditions` | 只摘出来源给出的理由和会改变判断的前提，例如适用项目、批次、测算口径。未提供时相应列表留空。卡面需要交代时写「原文未说明依据」。 |
| `evidence` | 每处证据给固定段号和该段内连续的原句。判断和关键理由各有落点。一段支持两个不同判断时可共用段号，各自注明所据原句。 |

纯开场、版权说明等没有研究判断的组可交空列表。程序给观点分配稳定标识。独立校读同时验卡面和这份记录，后续知识总结直接使用签发版本。旧篇沿用已签发卡、已校读补写和固定原文。

## 排版与长文章层级

- 大标题直接写主张，正文接着写作者的推导、理由和具体支撑。条目要能独立读懂，原文链接负责核对证据。正文的字重、字号和行距以在 Obsidian 常用窗口中直接读懂为准。
- 先判断多点一步能读到什么。一个判断和理由在一张卡上能讲清就直接呈现。作者分别论证几条主线时，可以并列入口。只有原文确有总论点才写共同结论。同一主线下各自成立的子观点并排，展开后给本支新增的理由、条件或原文证据。仅因篇幅长而换列时沿用原主线。程序按分组排版和上色。
- 实测阅读视图与编辑视图。生成管理标记、模板占位符和维护说明存放在独立文件，不出现在阅读材料中。样例确认后再按范围更新历史文章。

## 独立校读

- 单独阅读标题和卡面正文，核对它们能否表达一条完整论证。再和固定段落逐项核对主张、因果方向、归属、数字、关键条件及话题边界。
- 卡面缺少正文或必要推导时，指出需要补写的判断和对应原文编号。涉及两个独立主题或证据落在相邻组时，明确建议重划边界。每轮返工和复核沿用本标准。

## 减少重复研读和返工

1. **首稿一次完成分组与卡面。** 先用标题和段落编号定位文章主线，再通读本分区，按能独立成立的判断分组。每组确定主体、判断、决定性依据和适用条件后直接写成卡。完整原文由程序附上，背景、复述和旁支例子留在完整阅读。
2. **提交前逐卡对照容易出错的点。** 检查事实、推测和转述的归属，关键数字的单位、样本口径和时点，以及会改变判断的前提与反例。优先在首稿补齐这些信息，同时检查相邻卡片的分界和段号覆盖。
3. **独立校读一轮报齐实质问题。** 首次对照本分区全部原文。每条问题写明卡片起始编号、证据编号和必须修改的字段。相同根因合并为一条，彼此独立的问题分别列明。正文遗漏按内容问题处理。涉及相邻组的边界问题写清原文哪个编号应移动以及移到哪里。
4. **返工限于明确的范围。** 按收到的问题单一次修完同一卡的相关字段，并保留已校读通过的卡片。少量边界问题优先在允许替换的连续区间内调整。必要证据或可调整的边界在给定范围之外时，返工轮按约定返回空 `groups`，由 AFR 扩大证据范围。复核先检查改动、原问题和相邻边界，签发按完整分区校验。

## 与全库白板的衔接

- 阅读首页、资料档案导航、文章主题和篇内论述的主要阅读入口使用 Obsidian 白板。每个论点从卡面进入独立的论述白板，标题概括原作者的观点，正文按阅读顺序写出支撑观点的原因、推导或例子，紧跟可定位的固定原文链接。
- 用同一个低饱和浅色贯穿一条观点链。正文和引文保持可读，卡片之间留出明确空间。保留固定原文、签发内容、既有路径和手写材料。
- 已签发资料若只改展示，复用原来的研读、校读和签发记录，本机重绘。知识主题白板的按月选读、两列时间线与逐段回源遵循《知识总结 Agent 运行标准》。

## 正式库归档与重复入口

- 库根目录保留「AFR 阅读首页」白板、资料档案和知识总结三个入口。既有文章按实质领域归入资料档案，每篇保留一个目录和固定原文。已签发的旧「待整理」按实际内容归档，读取不完整的材料在「资料档案／读取核验」记录具体缺口。
- 知识总结按分类放置主题文件夹，分类白板在本分类目录内。每个主题目录只有一张问题主白板和其下的具体论述。禁止新增平铺主题、重复入口和单独批次总结。归档时按签发身份迁移并保留可追溯的原文锚点与用户笔记。
