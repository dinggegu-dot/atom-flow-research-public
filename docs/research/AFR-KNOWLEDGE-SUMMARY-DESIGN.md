# AFR 知识总结 Agent 设计

2026-11-25，用户确认由知识总结 Agent 接替研究问题 Agent，按对象和持续跟踪维度归类。用户投放一篇材料后，可以先在 Obsidian 白板读懂文章，再从知识白板时间线看它补充了哪条知识、改变了哪个判断，并点回当时的原文。

## 读者怎样验收这次修改

打开新研报的第一张白板，读者应能复述「谁得出了什么判断、凭什么、什么条件下成立」，并点回那句话。以后有同主题材料，读者应能分清多了一份出处、多了一项进展，还是两家判断不同。从总白板点入每一级都应看到比上一级多一层的理由，只有一个完整判断时直接给原文入口。

例如第一份报告披露减速器送样，第二份报道转述同一公告，第三份披露量产。预期时间线有送样和量产两项，送样下可看两份出处。如果另一位作者只预测量产，卡面标明预测及其依据。不同作者的分歧并列，来源明确更正时才替代旧判断，旧版本始终可回读。

## 两个 Agent 的交接

- 分类／文章 Agent 按文章主线制作篇内白板，卡片保留完整论述、条件、例子和固定原文锚点。示例文章的 15 张卡是这篇文章的阅读样例，全库主题随实际要积累的内容组织。文章白板可以先交付阅读。
- 知识总结 Agent 从已校读的篇内卡中提取可独立验证的主题更新。每条更新记录对象、要积累的维度、具体事实或观点、适用范围、日期和固定原文锚点。一张卡可以贡献多条更新，主题笔记读者可以沿引用回看整段论证。

## 知识分类与白板导航

总白板的浏览路径是「领域 → 分类名总览 → 问题主白板 → 具体论述 → 固定原文」。六个领域用不同的低饱和浅色区分，各分类入口显示主题数量。分类总览的主题卡给出核心判断、跟踪范围和一到两条直接相关的记录。标题进入问题主白板，具体记录的链接进入对应论述。同排卡片等高，主题卡沿用主题时间线的配色。

| 领域 | 正式库当前显示的分类 |
| --- | --- |
| 科技与产业 | 半导体与存储 / 算力与通信基础设施 / AI 应用与商业化 / 具身 AI · 现场部署 / 生物制造与新产业 / 资源、农业与公用事业 |
| 宏观与金融 | 货币、汇率与信用 / 资产定价与市场策略 / 地方财政与基建 |
| 企业与投资 | 经营模式与转型 / 企业融资与项目 |
| 治理与地缘 | 贸易通道与政策 / 地缘冲突与外部影响 / 区域发展与产业政策 |
| 社会与劳动 | 劳动、就业与分配 / 家庭与机会 |
| 认知与方法 | 研究与证据 / 组织、决策与协作 |

每个主题根据「具体对象 × 持续跟踪维度」选一个主分类。具身 AI 的技术投入、核心零部件和现场部署分别归类，有主题时才显示相应入口。归属确实不清楚时进「待归类」。新证据补充已有主题时，沿用其分类、主题 ID 和时间线路径。分类判定与输出字段见 [知识总结 Agent 运行标准](../../afr_agent/KNOWLEDGE-SUMMARY-STANDARD.md#知识总白板分区)。

2026-11-26 正式库验收覆盖 58 个主题、6 个领域和 18 个已使用的分类。基于原来的 817 条记录完成归类，原主题笔记和时间线保留。实测从总白板点进「科技与产业 → 半导体与存储」，能看到 HBM 的投资动向、潜在供应和待观察项，再打开原时间线。

## HBM 样式和材料时间

主题时间线的每张卡先显示材料的具体结论，再标材料时间、来源和判断性质，按需要补充原因、测算、待核实的地方以及固定原文链接。

材料时间取首次核验投放原件时的最后修改时间，按北京时间显示。同日用精确修改时间排序。研报里的年份、发表日期及预测目标保留在内容和出处中。原件时间缺失的历史材料标为待核。新增记录按原主题接续，时间线保留旧记录和原文入口。

收录时仅对没有实质文件名的材料按日期命名，保留扩展名。用 `2026年10月13日.docx` 这类日期格式，同日多份按修改时间先后追加 `-01`、`-02` 等序号。已有标题或日期文件名继续可用，后来到的同日材料顺延。

## 下一轮调度原则

- **小批投放，凑齐就总结。** 文章白板逐篇签发，全部签发后立即启动知识总结。常规等待到期时，如果只剩一篇且已进入签发前校读，允许额外等一次，试验上限为 5 秒。它一签发就开工，额外等待到期也开工。最后一篇失败、等待重试或需要人工处理时，用已签发材料继续。
- **持续大批投放，按主题分批更新。** 一个主题的已签发证据够用，就在规定的等待时间内安排校读和发布。后续签发的文章只补到它直接涉及的主题，避免重复比较整批资料。
- **单篇可以先立题，后续接着写。** 文章签发后，从篇内卡保留具体对象、跟踪维度、来源和固定原文位置。没有共同主题时，单篇有值得跟踪且原文说得清楚的内容，就可以先建一个主题。例如一篇材料证实某项目的减速器开始送样，就记下送样和原文出处。以后有量产或交付消息时，找回当次获准比较的旧证据，核对零件和项目，把新进展按时间接到原来的白板上。同源转载和重复转述沿用已有记录。

复测沿用本次对照的五篇研报。在最后一篇分别于额外等待内签发、超时和进入重试时，核对知识批次何时开始。记录首篇白板可读、全部文章签发、有效知识发布和模型调用次数。另验收一篇材料能否单独建立有原文出处的主题，以及晚到材料能否补到同一时间线并保留原有记录和手写区。

文章 Agent 在首稿与独立校读时一起完成观点、发言者、判断性质、依据、前提和逐字引文。程序负责稳定标识、固定链接、材料日期、位置和配色。知识总结复用这份签发结果，只比较当批许可的相关证据。旧签发卡照常参与。修改字号、排版和导航时，读取本机签发结果重绘相应视图，模型调用应为零。

验收从同一次投放起分别量首篇在索引可打开、全部文章签发、知识结果发布。区分有新事件、只补出处、校读后无合格增量，并核对回执。模型处理与队列、写入、重试等待分开计时。文章签发后遇到索引写入故障只续办索引，知识已校读后写入故障沿用保存的结果。

## 跨篇归类

先明确材料具体在说什么对象，再判断这条内容能补充哪个长期积累的维度。比如同一家人形机器人厂商可以分别积累技术投入、核心零件供应链、现场部署。归类以原文证据为依据，遇到对象、阶段或归属不明时，先保留在篇内白板或提交待确认。

| 积累维度 | 具身 AI 示例及记录方式 |
| --- | --- |
| 技术投入 | 分别记录意向、审批、签约、付款和实际建设、投产，附日期、金额或进度及其口径。各阶段可以并行、延期、取消或分批发生。董事会批准投资 10 亿元、首期支付 2 亿元和一条产线投产是三个记录，各自按证据填写。实际建设由施工或设备进场等证据支持，金额未知就留空。 |
| 核心零件供应链 | 六维力传感器获整机厂定点，记录供应商、零件、整机或项目及定点阶段。样件、量产和实际交付分别依证据更新。 |
| 现场部署 | 某工厂已有 10 台机器人承担夜班搬运，记录站点、任务、数量和证据日期。试点、生产部署、规模化推广分别按现场证据记录，效果指标附上量测条件。 |

同一段材料同时证实多个可分别积累的事实时，可以从同一处原文锚点更新多个主题。例如「整机厂收到首批 20 套力传感器，其中 10 台装配后已在某工厂值夜班」同时支撑零件交付和现场部署。只有技术背景或上下游关联时，在相关主题放链接。转载及同一事件的重复转述沿用同一事实记录和原始出处，独立证据证实同一判断时补在原记录下，有新阶段或条件变化时追加时间线。

已有主题随一条有实质变化的材料更新，例如状态推进、条件变化、新证据或更正。一篇材料有明确的对象、值得持续跟踪的内容和可回查的原文，就可以单独建立知识主题。多个独立来源提供的事实或观点可以在同一主题中逐条补充，各自注明来源和适用范围。用户指定跟踪的主题可以直接建立。同一材料多次讨论同一主题时合成一次时间更新，保留各段固定出处。

## 白板配色

两类白板共用低饱和浅色。一个论述链的卡片、标签、连线和续列同色，不同链使用可辨别的浅色。文章白板按文章主线成链，知识白板按知识主题的时间线成链。白板入口使用独立的浅色中性色，每条链也有文字标签。

## 历史和写入边界

- 知识总结 Agent 写入获准维护的主题生成区及其更新历史。主题记录分清来源观点、Agent 综合和用户判断。新增材料出现分歧时并列写明来源和条件，有证据表明原判断被修订时，追加旧判断、新判断、变更日期、理由和各自的固定引用。分别记录来源发表、材料收录及判断更新日期。
- 固定原文、既有白板及其引用、人工笔记、用户判断与手工布局由现有写入权限保护。人工内容的更改由用户明确授权。历史研究问题移入库外恢复点，正式库保留知识总结与原始材料。此次实施与验收使用隔离库。

## 合成验收

在隔离库经正式投放入口，依次投放合成材料。以下为待执行验收。

1. 投放一篇披露拟投 10 亿元并获董事会审批的资料。Obsidian 先出现可阅读、可回原文的篇内白板，主题中可查到意向和审批，实际支付与建设字段留空。
2. 投放后续资料，分别披露首期付款、另一批次的一条线已投产，以及同一段中的零件交付和工厂夜班运行。核对阶段各自按对象、批次和日期更新，零件和部署入口都定位到支撑它们的原句。
3. 投放转载、带独立现场数据的报道，以及更正「运行 10 台」为「运行 8 台、2 台待调试」的原始披露。核对转载复用同一记录，新增现场证据可定位，更正后的当前判断和旧版本都可回看。再次投放同一文件，核对无重复更新，并检查人工区、历史研究问题和固定链接。

## 阅读首页与长时间线

打开「AFR 阅读首页」可以先看最近一批已可读的文章和已经发布的主题变化。文章白板一签发就显示，主题变化从发布回执取批次，点开直达具体论述白板。首页按实际签发和发布时间展示，时间线继续按原件修改时间排列。展开处理明细可看逐篇状态、排队与返工，以及从入队到首篇可读、全部可读、总结发布的耗时。历史回执缺失的字段直接标明缺失。

### 首页与卡片的呈现

首页用低饱和的雾蓝、灰绿和暖灰承载状态与分区，链接用深灰蓝，正文用深墨色。保持一个可见主标题。先看到投放和发布状态，再读文章与主题变化，可按需展开批次耗时。生成管理信息放进本机状态文件。阅读和编辑视图都检查可见文本。

以 Obsidian 正常阅读缩放下的桌面窗口为验收尺寸。样例卡标题约 23px、正文约 17px，正文行高约为字号的 1.55 倍，材料时间与来源略小。优先增加留白、卡面宽高或分层，以便让正文保持易读。相邻观点链的低饱和浅色可区分，链内部的二级和三级卡用同一色。用文字标明观点、预期和证据的层级。

### 一题一板与详细论述

一个知识问题用一张主白板。把问题范围、已有分论点、按月选读和完整时间线放在同一张板上。具体分论点点开才进入详细论述，沿纵向读作者的理由和条件，逐段点回固定原文，再返回主白板。时间线每行从左到右最多两张，下一行和下个月都在下方。缩小时月份标签显示条数和一个具体观点。

日常生成要求见[知识总结 Agent 运行标准](../../afr_agent/KNOWLEDGE-SUMMARY-STANDARD.md)和[文章 Agent 白板标准](../../afr_agent/ARTICLE-BOARD-STANDARD.md)。

## 从目录到一条具体论述

读者在文件列表看见中文主题，进入主题或时间线后，点一个具体判断即可打开它自己的论述白板。板上展示来源的理由、适用条件及可核对的原文，保留返回主题和继续读材料的入口。篇内卡按相同阅读方式打开对应的完整论述。内部记录 ID 用于去重、校验和接续历史。文件和链接显示可辨认的标题，同名时才补充区分信息。

材料按投放原件最后修改时间排列。缩小时读月份及判断提示，放大后每行最多两条，向下连续阅读。长材料保留选读和完整历史。旧研究问题、旧话题入口及对照表保存在库外恢复点，手写区和原件随迁移核对。


## 正式运行流程 · 2026-11-26

1. 向配置的投放目录放入研报。AFR 固定原件、原文和修改时间，保留本机收录版本。
2. 文章 Agent 按篇组织材料并独立校读。每篇一经签发，即可从「AFR 阅读首页 → 资料档案」按领域打开白板和原文。识别缺口在「读取核验」保留。
3. 知识总结 Agent 接收获准比较的签发材料。先判断具体对象与需要积累的维度，再匹配既有主题与分类。可以用一篇材料独立建立有出处的新题，迟签材料在后续批次补入。
4. AFR 追加实质进展，重绘对应问题白板、详细论述、所属分类总览及知识总结总白板，并在首页显示已发布变化。新增主题会更新分类数量。新增判断、补出处、分歧和更正各按自己的口径显示。
5. 已有成果只需换版式或修复导航时，用 `refresh-views` 从本机账本重绘。验收新资料时从 Obsidian 首页走到分类、问题、论述和固定原文，检查重放没有重复，用户笔记仍在。

正式库定稿时有 58 张问题主白板，归在 18 张分类总览中，共 817 条可定位的知识记录。分类表用于查看当前布局，模型收到的分类代码由 AFR 运行时提供。后续增量发布沿用相同结构。
